# Requirements: Structure map + structural questions (Task 3)

Two pure functions in `packages/core/src/`: `buildStructureMap` (AST map of JS/TS files) and `generateStructuralQuestions` (deterministic MCQs from the map, no AI). They are the quiz fallback in Task 4 and the only quiz in `--offline` mode, so they must never need the network and must give the same output for the same input. No I/O, no clock, no randomness, no env.

Changes made after the review of the first build are marked "(changed after review)". Changes made after the second review pass are marked "(changed after re-review)".

## Glossary
- **JS/TS file**: path ending in `.js .jsx .mjs .cjs .ts .tsx .mts .cts` (case-insensitive). Every other file is an **other file**.
- **Top-level function**: a function declaration, or a `const` initialised with an arrow function or function expression, at module top level (also inside `export` / `export default`).
- **Display name**: `fn` for a top-level function, `Class.method` for a method. A display name is **ambiguous** when it occurs more than once in the map. The display name `default` (an anonymous default-export function) is never used in questions. (changed after review)
- **Plain parameters**: every parameter is a plain identifier (with or without a type annotation or `?`). A default value, a rest parameter or a destructuring pattern makes the parameters not plain; a TS `this` parameter is ignored. (changed after review)
- **Relative module**: an import source starting with `./` or `../`. (changed after review)
- **Last segment**: the part of a name after the last `.` (`helper` for `obj.a.helper`; the whole name when there is no `.`). (changed after review)
- **Bytes**: UTF-8 length (`TextEncoder`).
- **Mentioned name**: any identifier, JSX identifier or string-literal computed member name (`obj["x"]`) that appears in a function's parameters (defaults included) or body, wherever it appears: a call, an argument, an alias, a tagged template, a member (`helper.call(null)`). (changed after re-review)
- **Ancestor classes**: for a class with `extends S`, every class in the map named `S`, then the ancestors of those, found by name inside the map. The chain stops on a repeated name (cycle). (changed after re-review)

## 1. `buildStructureMap(files)`
1.1 THE SYSTEM SHALL return `{ schemaVersion: 1, files }` with one entry per input file, sorted by path (code-unit order).
1.2 THE SYSTEM SHALL normalise each path by replacing `\` with `/`, collapsing repeated `/`, removing every `.` segment (`./` at the start or anywhere inside, so `a/./b.ts` is `a/b.ts`) and removing a leading `/` and a trailing `/`. (changed after review)
1.3 WHEN a file is a JS/TS file, THE SYSTEM SHALL parse it with `@babel/parser`, using the `typescript` plugin for TS extensions, `jsx` for `.jsx .js .mjs .cjs .tsx`, the `decorators-legacy` plugin for every JS/TS file, `dts: true` for `.d.ts`, `.d.mts` and `.d.cts`, and `errorRecovery: true`. (changed after review)
1.4 THE SYSTEM SHALL parse with `sourceType: "module"`. WHEN that throws or records errors, THE SYSTEM SHALL also parse with `sourceType: "script"` and keep the result with fewer recorded errors; a parse that throws counts as worse than any parse that returns; on a tie the module result wins. (changed after review)
1.5 THE SYSTEM SHALL record imports: source module, kind (`import` or `require`), default and namespace local names, imported names, and `typeOnly`. Top-level `const x = require("m")` and `const { a } = require("m")` with a string literal count as `require` imports.
1.6 THE SYSTEM SHALL record exports: named (by exported name), default, and re-exports (`export { a } from`, `export * from`, `export * as ns from`) with their source module. Named exports include: every name bound by `export const { a, b: { c }, ...r } = x` and `export const [d, [e], ...f] = y` (nested, with defaults and rest); `export namespace NS {}` and `export module M {}` (named by the first identifier of the name); `export import X = require("m")` and `export import X = A.B`; and TS interface, type and enum declarations. `export = foo` is a default export named `foo` (`default` when the expression is not an identifier). (changed after review)
1.7 THE SYSTEM SHALL record each top-level function with name, parameter count, `plainParams`, `async`, `exported`, start line, `calls`, `calledNames` and `mentionedNames`. An anonymous default-export function is named `default`. (changed after review; `mentionedNames` changed after re-review)
1.8 THE SYSTEM SHALL record each top-level class with name, `exported`, start line, and methods (class methods and class properties holding an arrow/function, excluding `constructor`, getters and setters), each with name, parameter count, `plainParams`, `async`, `static`, start line, `calls`, `calledNames` and `mentionedNames`. (changed after review; `mentionedNames` changed after re-review)
1.8a THE SYSTEM SHALL record on each class `superClass`: the text of the `extends` expression when it is an identifier or a chain of non-computed members (`Base`, `React.Component`), and the text `(expression)` for any other expression (`extends mixin(Base)`); the field is omitted when the class has no `extends`. THE SYSTEM SHALL also record `accessors`: the sorted, deduped names of the class's getters and setters (these are not in `methods`). (changed after re-review)
1.9 THE SYSTEM SHALL record as `calls`, for each function or method, every call whose callee is an identifier (`foo`) or a non-computed member of an identifier or `this` (`obj.foo`, `this.foo`), including calls inside nested functions and inside parameter default values (`function f(a = helper())`); other callees are skipped. (changed after re-review: parameters are walked too)
1.9a THE SYSTEM SHALL record as `calledNames` the last segment of every call in the same parameters and body, including member chains (`obj.a.helper()` gives `helper`, `this.db.get()` gives `get`) and string-literal members (`obj["x"]()` gives `x`). Computed non-string members, private names and calls on call results (`make()()` gives only the inner `make`) add nothing beyond what their own callee gives. `calls` is always a subset of `calledNames` by last segment. (changed after review)
1.9b THE SYSTEM SHALL record as `mentionedNames`, for each function or method, the sorted, deduped list of its mentioned names (see Glossary), at most 500. WHEN a function would have more than 500, THE SYSTEM SHALL keep the first 500 in sorted order, and a list of exactly 500 means "possibly cut". (changed after re-review)
1.9c THE SYSTEM SHALL record CommonJS exports of the top-level statements of a file as `commonjsExports` (sorted, deduped names) and `hasUnknownExports` (boolean). Names come from `exports.x = ...`, `exports["x"] = ...`, `module.exports.x = ...`, chained assignments, `module.exports = { a, b: c, d() {} }` (shorthand, keys and methods), `Object.assign(module.exports, { a })` and `Object.defineProperty(exports, "x", ...)`. `module.exports = <anything that is not an object literal>` records the name `default`. `hasUnknownExports` is true when a name cannot be read: `module.exports = something`, a spread or computed key in the object, a computed `exports[name] =`, an `Object.assign` with a non-literal source, or an `Object.defineProperty` with a non-literal name. The ES `exports` list is not changed by any of this. (changed after re-review)
1.10 THE SYSTEM SHALL sort and dedupe every list of names and order every list of entries by a fixed key (see design), so the output does not depend on source order or input order. Methods are ordered by (name, static, line) and then by JSON text, so two different entries never tie. (changed after review)
1.11 WHEN a file is an other file, THE SYSTEM SHALL record only path, language from the extension, and line count, with empty lists.
1.12 THE SYSTEM SHALL count lines as the pieces after splitting on `\r\n`, `\r` or `\n`, not counting a final empty piece (`""` -> 0, `"a\n"` -> 1).
1.13 IF parsing fails in both source types, THEN THE SYSTEM SHALL set `parsed: false`, record the error of the module attempt, leave the lists empty (`commonjsExports: []`, `hasUnknownExports: false`), and continue with the other files. WHEN the parser overflows its stack on deeply nested input (about 500 levels), THE SYSTEM SHALL record the message `nested too deeply to parse` instead of the raw engine message. (changed after review)
1.14 WHEN parsing succeeds with recovered errors, THE SYSTEM SHALL set `parsed: true`, extract what it can, and record up to 10 errors (`{ message, line }`).
1.15 THE SYSTEM SHALL never throw because of file content.
1.16 IF there are more than 50 files, or the total content exceeds 102 400 bytes (100 KB), THEN THE SYSTEM SHALL throw a RangeError naming the limit. THE SYSTEM SHALL check the running character count first and reject before UTF-8 encoding anything once it exceeds the byte limit (a string never has fewer bytes than characters). (changed after review)
1.17 IF a path is empty, or two paths are equal after normalisation (`././a.ts` and `a.ts`, `a//b.ts` and `a/b.ts`, `a/./b.ts` and `a/b.ts`), THEN THE SYSTEM SHALL throw a RangeError. (changed after review)
1.18 THE SYSTEM SHALL export the limits as `MAP_LIMITS = { maxFiles: 50, maxTotalBytes: 102400 }`.

## 2. `generateStructuralQuestions(map, options?)`
2.1 THE SYSTEM SHALL return `StructuralQuestion[]`, each assignable to Task 2's `QuizQuestion` with kind `"mcq"`, plus `prompt` and `source: { path, line }`.
2.2 THE SYSTEM SHALL build candidate questions from the six templates in design (concepts `exports`, `imports`, `call-graph`, `classes`, `async-functions`, `parameters`).
2.3 THE SYSTEM SHALL take every choice from real paths or names in the map, except the `parameters` template, whose choices are integer strings.
2.4 THE SYSTEM SHALL make exactly one choice correct: a distractor must be false for the question asked.
2.5 THE SYSTEM SHALL never use an ambiguous display name, or the display name `default`, as a subject or a choice. A class named `default` is not asked about either. (changed after review)
2.6 THE SYSTEM SHALL give each question 2 to 4 unique choices; IF a candidate has no valid distractor, THEN THE SYSTEM SHALL skip it.
2.7 THE SYSTEM SHALL give each question a stable id `<template>:<subject key>`, unique within the result.
2.8 THE SYSTEM SHALL pick distractors and order questions with FNV-1a 32-bit hashes of `seed` and question id, and order choices with hashes of `seed`, `attempt`, question id and choice text; no `Math.random`.
2.9 THE SYSTEM SHALL interleave the templates round-robin in this fixed order: `caller`, `class-method`, `import-from`, `export-owner`, `async-pick`, `param-count`. The seed only chooses which candidate comes next inside a template. (changed after review)
2.10 THE SYSTEM SHALL return at most `count` questions (default 5), fewer when there are fewer candidates, and `[]` for a map with no candidates (e.g. empty, only other files, or one file with a single `const`).
2.11 WHEN called twice with deep-equal map and options, THE SYSTEM SHALL return deep-equal results.
2.12 WHEN `count` grows, THE SYSTEM SHALL return a result that starts with the smaller result (stable prefix). THE SYSTEM SHALL build candidates lazily, one at a time in that order, and stop once `count` questions exist; a candidate that cannot be built is skipped. (changed after review)
2.13 IF `count` is not an integer in 0..50, or `seed` or `attempt` is not a non-negative safe integer, THEN THE SYSTEM SHALL throw a RangeError.
2.14 THE SYSTEM SHALL skip files with `parsed: false` and other files.
2.15 WHEN only `attempt` changes, THE SYSTEM SHALL return the same questions (same ids, same prompts, same set of choices, same correct choice text) with the choices in a different order where possible, so a retake cannot be passed by remembering answer positions.
2.16 THE SYSTEM SHALL ask `caller` only about callees that resolve inside the project, judged for each calling function: a bare identifier equal to the name of a top-level function in the map, or to a name imported from a relative module in the caller's file; `this.m` where `m` is a method of the calling class; `obj.x` only when `obj` is a namespace import from a relative module in the caller's file. Every other callee (`console.log`, `obj.x` on a variable, `Math.max`) is never a subject. (changed after review)
2.17 THE SYSTEM SHALL NOT offer a `caller` distractor whose `calledNames` or `mentionedNames` contains the last segment of the subject, nor one whose own name has that last segment. A function that calls `obj.a.helper()`, passes `helper` as a callback (`list.map(helper)`, `app.get("/", helper)`, `.then(helper)`), aliases it (`const h = helper; h()`), uses it in a default parameter, or mentions it in any other way (`helper.call(null)`, `helper.bind(null)()`, a tagged template) is therefore never a wrong answer to "which function calls `helper`?". A parameter that is named like the subject (`function f(helper) { helper(); }`) counts as a mention, so `f` is accepted as a caller (open question 25). (changed after re-review)
2.18 THE SYSTEM SHALL ask `param-count` only about functions with plain parameters. For a function with `p` parameters, THE SYSTEM SHALL pick the three wrong answers with the same hash-based picker as every other template, from `p-2`, `p-1`, `p+1`, `p+2`, `p+3` keeping only values >= 0 (so the correct answer is not always the second-lowest choice). On `attempt` 0 the choices are shown in ascending numeric order; on any later attempt they are shuffled like all other choices, so req 2.15 still holds. For `p` = 0 the correct answer is always the lowest number, so it is first on `attempt` 0; that cannot be avoided with ascending order. (changed after re-review)
2.19 THE SYSTEM SHALL name the file in the prompt of `caller`, `async-pick` and `param-count` (path as stored in the map) and, for `caller` and `async-pick`, take every choice from that same file, so the prompt is true for every choice. The file of a `caller` question is the file of the correct function. (changed after review)
2.20 WITHIN the limits of `buildStructureMap` (50 files, 100 KB) and for any `count`, THE SYSTEM SHALL return in under 1 s on a typical laptop; for 1,000 functions or 2,000 classes with `count: 5` it SHALL return in under 500 ms. (changed after review)

2.21 THE SYSTEM SHALL NOT offer as a `class-method` wrong answer any method, getter or setter name of the subject class, nor of any ancestor class of it (see Glossary). WHEN the subject class has an `extends` and any class in its chain is not in the map (`extends React.Component`, `extends mixin(Base)`, an imported class), THE SYSTEM SHALL skip the `class-method` question for that class, because the inherited names are unknown. (changed after re-review)
2.22 THE SYSTEM SHALL NOT offer as an `export-owner` wrong answer a file whose `commonjsExports` contains the subject name, nor a file whose `hasUnknownExports` is true. (changed after re-review)

## 3. Module layout
3.1 THE SYSTEM SHALL put the functions in `structure-map.ts` and `structural-questions.ts` with `*.test.ts` beside them, and re-export public names from `index.ts`.
3.2 THE SYSTEM SHALL add no dependencies beyond the installed `@babel/parser` and `@babel/types` 7.29.14.
3.3 Fixtures SHALL live in `packages/core/fixtures/`; only tests and scripts read them.

## Open questions (defaults chosen)
1. **Over-limit input: throw, not truncate.** PRODUCT DECISION. A silent cut would quiz on part of the change without saying so. Callers trim: `sync` (Task 6) keeps the most-changed files, the API (Task 8) returns 413. Same 100 KB as the API cap.
2. **`prompt` is not in Task 2's `QuizQuestion`.** `StructuralQuestion` is an intersection type that adds `prompt` and `source`; `scoreQuiz` ignores extra fields, so Task 2 is unchanged. Task 4 will need prompts for AI questions too; it should then add `prompt` to `QuizQuestion` itself.
3. **Question templates and concept tags.** PRODUCT DECISION. The six tags become SM-2 card names, so renaming them later orphans saved cards. Yes/no questions ("Is `fn` async?") were dropped because their choices are not map names; "Which of these is async?" asks the same thing.
4. **Ambiguous names are skipped** rather than shown as `fn (src/a.ts)`, to keep choices short for beginners.
5. **CommonJS:** top-level `require` is mapped. (changed after re-review) `module.exports` and `exports.x` are recorded in separate fields `commonjsExports` and `hasUnknownExports` (req 1.9c); the ES `exports` list stays empty for them, so they are never asked about as a subject, but they keep a file from being a wrong answer to `export-owner` (req 2.22). Only top-level statements are read: `if (x) { module.exports = ... }` or a UMD wrapper is not seen. Dynamic `import()` is not mapped.
6. **JSX in `.js` files** is enabled, since React projects often use it. TS generics like `<T>(x) =>` in `.ts` stay valid because `jsx` is off there.
7. **Line endings and BOM:** content is parsed as given; a leading BOM is allowed by Babel.
8. **Seed and attempt:** DECIDED (Vedant). `seed` (default 0, one per sync) fixes which questions and distractors appear, so demos are repeatable. `attempt` (default 0, +1 per retake) only reshuffles choice order (req 2.15), so in strict mode a user cannot pass a retake by memorising "it was C".
9. **Concept granularity:** tags are per concept, not per name (`call-graph`, not `call-graph:loadUser`), so one SM-2 card covers a skill.
10. **(found during build) E1 contradicted req 1.9.** E1 listed `this.db.get` as a call of `findUser`, but req 1.9 only allows `obj.foo` and `this.foo`; the callee `this.db.get` is a member chain. The code follows req 1.9, and E1's test expects `calls` `["log"]` (it proves that member chains are skipped from `calls`). (changed after review: `calledNames` now records `get`, see 1.9a; design E1 matches.)
11. **(found during build) `Extract<QuizQuestion, { kind: "mcq" }>` is `never`.** The first member of `QuizQuestion` has `kind: "mcq" | "what-if"`, which does not extend `{ kind: "mcq" }`. `StructuralQuestion` is therefore written out as its own interface with `kind: "mcq"`; a test checks it is assignable to `QuizQuestion[]` and passes through `scoreQuiz`. (changed after review: design.md now shows the interface that shipped.)
12. **(found during build) Ambiguity counts entries, not files.** A display name that occurs twice in one file (for example a static and an instance method with the same name) is also skipped, so a choice list can never hold two different things with one name. The same rule applies to class names for `class-method`.
13. **(found during build, replaced after review) `caller` distractors.** The first build excluded distractors that call anything with the same last name, but only from `calls`, so `obj.a.helper()` slipped through. Req 2.16 and 2.17 now define which callees may be asked about and exclude distractors by `calledNames`.
14. **(found during build) A file with a single function is not "tiny".** Every pooled function with plain parameters gets a `param-count` question (nearby numbers as wrong answers), so one such function is enough for 1 question. Only maps without such functions, such as a file with a single `const`, give `[]`.
15. **(found during build) Export details the spec left open.** TS `interface`, `type` and `enum` declarations count as named exports; `export { a as default }` is a default export named `a`; repeated overload exports are recorded once. `export default interface I {}` is recorded as the default export named `default` (no function entry). `export declare function f(): void;` records the export `f` but no function entry, because it has no body. (changed after review: the last two sentences.)
16. **(found during build) Shared test generator.** `arbProject` is used by both test files, so it lives in `packages/core/src/test-support/arb-project.ts` and is excluded from the build in `packages/core/tsconfig.json` (it imports fast-check, a dev dependency). `tsconfig.check.json` still type-checks it.
17. **(changed after review) Quadratic runtime.** The first build took 22 s for 4,000 functions in 100 KB and 7.8 s for 2,000 classes, because every template built every question before the first `count` were chosen. Candidates are now cheap objects built lazily (req 2.12, 2.20, design). SPEC GAP: the spec had no performance requirement; req 2.20 adds one.
18. **(changed after review) Decorators.** `@Component({...}) export class A {}` made Babel throw (`parsed: false`), so Angular/NestJS-style files vanished from the map. `decorators-legacy` is enabled for every JS/TS file (req 1.3). Probed with Babel 7.29.14: it combines with `typescript`, `jsx` and plain JS. Known limit: the legacy plugin rejects the newer `export @dec class A {}` order; such a file gets `parsed: false`.
19. **(changed after review) Script fallback.** Module mode records `with` statements and legacy octal literals as recoverable errors instead of throwing, so the old "retry on throw" never fired for them. Req 1.4 now compares both modes.
20. **(changed after review) Deep nesting.** Babel itself overflows its stack at about 500 levels of nesting (probed: 300 parses, 500 throws). The call walk uses an explicit stack, but the parser does not, so such files are `parsed: false` with the readable message of req 1.13. The earlier claim that a 5000-deep file "cannot overflow" was wrong.
21. **(changed after review) `param-count` order versus `attempt`.** Ascending numeric choices are easier to read, but a fixed order would let a retake be passed by remembering the position (open question 8). Decision: ascending on `attempt` 0 only (req 2.18). If you prefer always ascending, req 2.15 no longer holds for this template.
22. **(changed after review) Same-file choices.** Putting the file in a prompt ("In `a.ts`, which function is async?") is only true if every choice lives there, so `caller` and `async-pick` draw their wrong answers from that file (req 2.19). The cost: a file with a single function yields no such question; `param-count` and the other templates still do.
23. **(changed after review) Known limits of "calls".** A function passed as a callback (`list.map(helper)`) is not recorded as called, and `import { a as b }` records `a`, not `b`, so a bare call `b()` is not matched to the import. Both only make the generator skip or under-ask. (changed after re-review: the earlier sentence "unless a callback holder is offered as a wrong answer, which is accepted" is withdrawn. A callback holder is now never offered, because `mentionedNames` excludes it, req 2.17.)
24. **(changed after review) Task 8 must validate the map.** `generateStructuralQuestions` trusts its input. The hosted API (Task 8) receives a `StructureMap` from outside and SHALL validate it with a zod schema with caps (for example 50 files, 500 entries per list, 200 characters per name, `schemaVersion: 1`) before calling the generator. Nothing is built for this in Task 3. Reminder also in PROJECT.md "Key decisions".
25. **(changed after re-review) Shadowing is not resolved.** `mentionedNames` is a list of names, not of bindings. In `function f(helper) { helper(); }` the parameter `helper` shadows a project function `helper`, yet `f` is accepted as a caller of the project's `helper` (`calls` has `helper`, and `f` resolves it by name). The same name check keeps `f` out of wrong answers, which is the safe side. Handling scopes would need a scope analysis; the answer stays correct only when the learner reads the name as the project function. Accepted for a beginner quiz; a quiz about shadowed code should not use `caller`.
26. **(changed after re-review) Same-file distractors exposed inheritance and CommonJS gaps.** Once `caller` and `async-pick` drew wrong answers from one file, the second review pass checked the other templates the same way: `class-method` offered `Base.save` as a wrong answer for `Admin` (which inherits it), `export-owner` offered a CommonJS file that exports the name, `caller` offered a function that passes the subject as a callback, and `param-count` showed the correct answer as choice B on the first attempt (the wrong answers were p-1, p+1, p+2 in ascending order, so p-1 always sat below it). Requirements 1.8a, 1.9b, 1.9c, 2.17, 2.18, 2.21 and 2.22 close these.
27. **(changed after re-review) Known limits of inheritance.** Ancestors are found by class name inside the map, so two classes with the same name in different files are both treated as ancestors (more names excluded, never fewer). Body-less members (`abstract save(): void;`, overload signatures) are in neither `methods` nor `accessors`; a name that is only declared abstract in an ancestor can still be offered as a wrong answer. Mixins and class factories are treated as an unknown superclass (`(expression)`), so no `class-method` question is made for them. A function with exactly 500 mentioned names is treated as "possibly cut" and is never offered as a `caller` wrong answer.
