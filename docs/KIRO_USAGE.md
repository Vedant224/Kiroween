## 3. Agent hooks
| Hook | Trigger | What it automates |
|---|---|---|
| `test-core-on-save` | PostFileSave, `packages/core/**.ts` | Runs vitest + fast-check on every core save |
| `log-usage` | Stop | Appends timestamp + `git diff --stat` to `docs/usage-log.md`; plain command, costs zero credits |
| `commit-after-task` | PostTaskExec (agent prompt) | After each spec task: run tests, update PROJECT.md/KIRO_USAGE.md, commit `Task N: ...`, push. Backs up the steering rule, which the model can forget |
| `seance sync` (product) | PostTaskExec | Updates PROJECT.md after each spec task _(Task 5/6)_ |
| dependency guard (product) | PreToolUse | Blocks `npm install <new pkg>` until approved _(Task 5)_ |

## Task log
### Task 1: Repo foundation (Nov 26, Vibe session, Sonnet 5.5)
- Kiro checked the hook trigger names and custom-agent schema on kiro.dev before writing any config, and recorded the verified trigger names in `tech.md`.
- The `security.md` rule "avoid versions published in the last 7 days" caught real cases: the latest vitest, fast-check and @types/node were 1 to 4 days old, so older pinned versions were chosen. A scan of the lockfile then found 4 transitive packages published in the last 7 days (`@types/estree`, `source-map-js`, `tinybench`, `tinyexec`); they are pinned to older versions with `overrides` in `package.json`.
- The installed npm 12.2.3 crashed during install (`Cannot read properties of null (reading 'edgesOut')` in arborist's peer-set loading). Workaround: `npx -y npm@11.21.3 install`.
- Always-on steering is 44 lines in total.
- Commit-and-push rule added in three places: a steering line (every chat sees it), the `builder` agent's prompt and permissions (`git add`/`commit`/`push origin main` allowed, force-push denied), and a `PostTaskExec` hook (fires even if the model forgets the rule).
